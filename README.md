# Techno Reward — اپلیکیشن موتور پاداش عملکرد شبکه فروش توسن تکنو

PWA مستقل (HTML/CSS/JavaScript، بدون Backend) برای محاسبه و تخصیص پاداش شریک‌ها و نماینده‌ها بر اساس فایل اکسل مدل مالی.
فونت: یکان (ضمیمهٔ ایمیل شما) · لوگو: توسن تکنو · همهٔ مسیرها نسبی است (سازگار با GitHub Project Pages).

## اجرای محلی
```bash
cd techno-reward-engine
python3 -m http.server 8080      # سپس http://localhost:8080
node tests/calculation-tests.js  # آزمون‌های محاسباتی (PASS/FAIL)
```
> Service Worker و نصب PWA فقط روی `https://` یا `localhost` کار می‌کنند؛ باز کردن مستقیم فایل (`file://`) برنامه را اجرا می‌کند ولی آفلاین/نصب ندارد.

## انتشار روی GitHub Pages
1. یک مخزن جدید بسازید (مثلاً `techno-reward`).
2. **محتوای** پوشهٔ `techno-reward-engine` (نه خود پوشه) را در ریشهٔ مخزن آپلود کنید: `index.html`، `sw.js`، `manifest.webmanifest`، `assets/`، `css/`، `js/`، `tests/`.
3. Settings ← Pages ← Source: *Deploy from a branch* ← شاخهٔ `main` و پوشهٔ `/ (root)` ← Save.
4. پس از ۱–۲ دقیقه آدرس `https://<user>.github.io/<repo>/` فعال می‌شود. یک‌بار بازش کنید تا آفلاین شود و سپس از منوی مرورگر «نصب برنامه» را بزنید.
5. با هر تغییر فایل‌ها، مقدار `CACHE` در `sw.js` (مثلاً `techno-reward-v5`) را افزایش دهید تا کاربران نسخهٔ جدید را بگیرند.

## فرمول‌ها (مطابق اکسل)
- `A3 = B3 + C3` ، `C5 = C3 − B5` ، `B8 = B3` ، `C8 = C3` ، `A8 = B8 + C8`
- `B13 = B12 + C12 + D12` ، `E13 = E12 + F12 + G12` ، `D14 = B13 + E13` (باید با `C8` برابر باشد؛ در غیر این‌صورت کنترل FAIL می‌شود)
- هر پاداش: `مبلغ = تعداد × نرخ`
- حق معرفی: `referralReward = referralRate × firstPurchaseDeviceCount` — فقط یک‌بار، فقط برای معرف مستقیم، فقط از خرید اولیه، و فقط پس از **تکمیل ثبت‌نام + تأیید مدارک + خرید اولیه**؛ تعداد معرفی‌ها سقف ندارد؛ به معرف هیچ «حق ثبت»ی بابت دستگاه‌های معرفی‌شده تعلق نمی‌گیرد
- حق ثبت/تارگت شریک: `B5` و `C5`؛ حق ثبت/تارگت نماینده: `B12` و `C12`
- حق ثبت قدیم/جدید به شریک (`F12`/`G12`): روی دستگاه‌های ثبت‌شدهٔ نمایندگان شبکهٔ شریک؛ «جدید» = دستگاه‌های خرید اولیه، «قدیم» = مازاد بر آن

## فرض‌هایی که اکسل صریح نگفته (تأیید شما لازم است)
همه در تب «فرمول‌ها و فرض‌ها» هم آمده‌اند. هر کدام در یک تابع جداست و تغییرش ساده است.
1. اعداد اکسل «به‌ازای هر دستگاه» هستند؛ بودجهٔ کل هر سبد = بودجهٔ هر دستگاه × تعداد دستگاه ثبت‌شدهٔ آن گروه (بدون سقف دستی).
2. سبد شریک فقط `B5/C5` را تأمین می‌کند؛ سبد نماینده شش حق بخش پایین جدول را (که سه‌تای آن به شریک می‌رسد).
3. تعریف «نماینده جدید/قدیم» و اینکه حق ثبت شبکه (قدیم/جدید) به شریکِ بالای زنجیر معرف‌ها می‌رسد؛ فیلد «شریک مربوطه» حذف شده و درخت معرفی جای آن را گرفته است.
4. هر نماینده یک معرف دارد؛ یا نماینده قدیم (`D12`) یا شریک (`E12`).
5. دادهٔ قدیمی فیلدهای «ثبت‌نام تکمیل» و «مدارک تأیید» نداشت؛ نمایندگانی که قبلاً خرید اولیه‌شان ثبت بود «تکمیل/تأیید» فرض شدند تا مبالغ قبلی تغییر نکند.
6. ابهام باز: `F12`/`G12` (حق ثبت نماینده قدیم/جدید به **شریک**) طبق اکسل دست‌نخورده ماند؛ اگر منظور از «حق ثبت به معرف» همین دو حق است لطفاً اعلام کنید.

## داده و حریم خصوصی
همه‌چیز در `localStorage` مرورگر ذخیره می‌شود و جایی ارسال نمی‌شود. از تب «داده و پشتیبان» پشتیبان JSON بگیرید. پاک‌سازی/بازیابی همیشه تأیید می‌خواهد و یک نسخهٔ قابل بازگردانی نگه می‌دارد.
